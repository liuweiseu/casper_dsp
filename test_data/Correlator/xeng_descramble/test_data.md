# xeng_descramble test data

`xeng_descramble` writes the X-engine's tap-ordered words to a RAM in element order (conjugating and swapping the last-triangle words) and reads every element out as `DEMUX_FACTOR` narrow words after `start_readout`. Stimulus: sync, three frames of NV valid words. For all but the last set the generator checks every readout against the element table computed from (line, tap) arithmetic (the appendix D map, itself checked against the plan's tables for N = 4, 6, 8), and that reads never hit the wide word being written. Every set shows the spontaneous power-on read pass (D*E valid words, no sync_out). The RAM powers up to the library initVector [1:36*8] (narrow word n = n+1, saturated to the output width, 0 beyond 288), as in Simulink.

Generated by `test_data/scripts/gen_correlator_test_data.py` from a cycle-level model of the casper_library diagram (not exported from MATLAB). Each `simdataN/` holds `params.json` (the testbench matches it against the DUT parameters) and one `sim_<port>.csv` per port: raw unsigned words in decimal, row i = value driven before / read after clock edge i.

**CSV data exported from the corresponding MATLAB Simulink block.**

Simulink data: the `sim_*.csv` files of sets 0, 1, 3, 5 were exported from Simulink models of the block (MATLAB R2021a, System Generator; plugins-demo2 export flow with its own random stimulus) and copied here on 2026-10-14; `params.json` (and any `.mem` files) are the generator's. The other sets keep the generated data (set 2: no Simulink equivalent (mapping `unsupported`); set 4: the Simulink output has a NaN, a RAM read/write collision that System Generator leaves undefined). Regenerating the module with its script replaces the exported CSVs with the reference model's output.
