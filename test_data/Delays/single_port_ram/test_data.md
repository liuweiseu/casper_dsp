# single_port_ram test data

`single_port_ram` is the Xilinx Single Port RAM with every mask option (memory type, write mode, latency, rst / en, optimize_latency, depth, initial contents), modelled as the block simulates in Simulink (see `docs/Delays/single_port_ram.md`). The first half of each run is write-heavy (75 % writes) to fill the memory, the second half read-heavy (25 % writes); every write is also a read-during-write of the same address. Sets with `RST` / `EN` drive random `sim_rst.csv` (rare, plus one mid-run) / `sim_en.csv` (70 % high); Distributed memory sets have no `sim_rst.csv` (the block has no rst port). Tests 6 and later start with an enabled read of every address in order, and those with an `INIT_FILE` load `ram_init.mem` from their directory (random raw words, one hex word per line; a file shorter than `DEPTH` leaves the other words 0). The other sets leave the options at their defaults (not in `params.json`).

Generated by `test_data/scripts/gen_delays_test_data.py` from cycle-accurate Python reference models of the documented behavior (not exported from MATLAB). Each `simdataN/` holds a `params.json` with the DUT parameters (the testbench uses the integer ones to select the data set), input values `sim_we.csv`, `sim_addr.csv`, `sim_din.csv` and expected output values `sim_dout.csv`, one per clock cycle. Expected outputs follow the pre-edge read convention: the value for cycle i is sampled after clock edge i but reflects the state before it, so the first latency cycles show the power-on state. The memory images of the sets with an `INIT_FILE` are `simdataN/ram_init.mem`.

Only `PLATFORM = "GENERIC"` (the default) is simulated here. The XILINX implementation is checked against GENERIC separately with Vivado xsim (`platform/xilinx/sim/run_xsim_equiv.sh`).

**CSV data exported from the corresponding MATLAB Simulink block.**

Simulink data: the `sim_*.csv` files of sets 0–5 were exported from Simulink models of the block (MATLAB R2021a, System Generator; plugins-demo2 export flow with its own random stimulus) and copied here on 2026-10-14; `params.json` (and any `.mem` files) are the generator's. Regenerating the module with its script replaces the exported CSVs with the reference model's output.

Sets 6–19 (added 2026-10-28) test the options added then (memory type, write mode, latency, optimize_latency, depth, initial contents). Their stimulus, `params.json` and `ram_init.mem` come from the generator; each set was then built as a Simulink model of the block (MATLAB R2021a, System Generator 2021.1; SNAP, RFSoC4x2 for the Ultra RAM sets 14–16) driven by that stimulus, and the simulated `dout` matches `sim_dout.csv` bit for bit, so these CSVs are the Simulink output. The behaviour the generator models was first measured on 37 exploratory Simulink configurations.
