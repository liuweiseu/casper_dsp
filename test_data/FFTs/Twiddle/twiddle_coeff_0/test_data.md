# twiddle_coeff_0 test data

`twiddle_coeff_0` delays every leg by `1 + MULT_LATENCY + ADD_LATENCY + CONV_LATENCY` cycles (w = 1).

Generated by `test_data/scripts/gen_twiddle_test_data.py` from cycle-accurate Python reference models of the casper_library behavior (not exported from MATLAB). Each `simdataN/` holds a `params.json` with the DUT parameters (the testbench matches the integer ones), and one `sim_<port>.csv` per port, one row per clock cycle; the lane ports (`ai_*`, `bi_*`, `ao_*`, `bwo_*`) have one file per lane instead, `sim_<port><j>.csv` = lane j. All values are raw unsigned bit patterns. Expected outputs follow the pre-edge read convention, so the first latency cycles show the zero power-on state. Cycles 1–4 drive the extreme words (most negative, most positive, −1, 0) on every lane; the rest are seeded uniform-random words. Sets with `ASYNC` = 1 drive a random enable (`sim_en.csv` / `sim_dvi.csv`, about 75 % high plus two 6-cycle gaps) and expect the valid output (`sim_dvalid.csv` / `sim_dvo.csv`) = the enable delayed with the data; only the twiddle_stage_2 select counter is gated (casper async, checked against Simulink, MATLAB R2021a).

**CSV data exported from the corresponding MATLAB Simulink block.**

Simulink data: the `sim_*.csv` files of sets 0–3 were exported from Simulink models of the block (MATLAB R2021a, System Generator; plugins-demo2 export flow with its own random stimulus) and copied here on 2026-10-14; `params.json` (and any `.mem` files) are the generator's. Regenerating the module with its script replaces the exported CSVs with the reference model's output.
